# Thermo Engineering — AI OS

AI-система подбора материалов, закупок и финансового учёта. Готовый пакет для запуска и переноса в облако.

## Что внутри
```
thermo-ai-os/
├─ src/
│  ├─ App.jsx          ← всё приложение (готовый код)
│  ├─ main.jsx         ← точка входа + shim хранилища
│  └─ db.js            ← облачный адаптер Supabase (для шага «Облако»)
├─ supabase/
│  └─ functions/ai-proxy/index.ts   ← серверная функция Claude
├─ schema.sql          ← структура БД для Supabase
├─ package.json, vite.config.js, index.html
├─ .env.example        ← шаблон ключей
├─ README.md           ← этот файл
└─ MIGRATION.md        ← перенос в облако, пошагово
```

---

## A. Запустить локально (сразу, без облака)

```bash
npm install
npm run dev
```
Открыть адрес из консоли (обычно http://localhost:5173).
Вход: **admin / admin123** → затем смените пароль в разделе «Аккаунты».

В этом режиме данные хранятся в браузере (localStorage) — для проверки функций. Для общей синхронной работы команды нужен шаг B (облако).

---

## B. Перенести в облако (Supabase + Claude)

Подробно — в **MIGRATION.md**. Коротко:
1. Создать проект на supabase.com, выполнить `schema.sql` в SQL Editor.
2. Получить API-ключ Anthropic на console.anthropic.com, задеплоить `ai-proxy`.
3. Подключить `db.js` и `ai-proxy` в `App.jsx` (3 замены, описаны в MIGRATION.md).
4. Прописать `.env` (см. `.env.example`), собрать `npm run build`, залить на Vercel/Cloudflare Pages.

## Если открываешь это в Claude Code

Дай агенту такую задачу:

> Это проект Thermo AI OS (Vite + React). Сделай:
> 1. `npm install` и проверь, что `npm run dev` запускается без ошибок.
> 2. Прочитай MIGRATION.md и подготовь приложение к Supabase: выполни 3 замены в `src/App.jsx` (подключить `./db`, убрать локальный data-layer, заменить `claudeCall` на вызов `ai-proxy`). НЕ удаляй бизнес-логику.
> 3. Спроси у меня SUPABASE_URL, ANON_KEY и подтверждение перед деплоем функции и фронтенда.

Claude Code умеет создавать проект, править код, писать SQL-миграции, коммитить и деплоить — это самый быстрый путь и для переноса, и для будущих правок.

## Аккаунты и роли
- **Руководитель** — полный доступ: дашборд, финансы, расходы компании, журнал действий, аккаунты.
- **Менеджер** — заявки, объекты, товары, склад, поставщики (видит долги/оплаты), мастера. Не видит прибыль/маржу и общий финреестр.

Аккаунты создаёт руководитель в разделе «Аккаунты». При переносе в облако вход заменяется на Supabase Auth (настоящая серверная авторизация).

## Основные разделы
Новая заявка (AI-распознавание текста/фото + подбор по базе) · Объекты (поставки, экспорт клиенту и листа доставки, финрасчёт) · Товары (импорт Excel) · Склад Thermo (приём возвратов, отгрузка) · Поставщики (оплаты частями по датам) · Мастера (бонусы деньгами/вещами) · Финансы (долги, расходы компании) · Дашборд · Журнал действий · Аккаунты.
